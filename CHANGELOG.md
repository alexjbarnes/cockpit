# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Fixed
- **A reset of the config no longer takes your trusted directories with it.** The reset drops the whole `projects` map, so every directory you had trusted starts asking again — which is why sessions in familiar repos began showing the trust card. The guard keeps the trusted list alongside the MCP servers and puts it back when it detects a reset, merging into whatever the CLI wrote for each directory; a directory you untrust deliberately stays untrusted.
- **A session in a directory Claude Code has not been told to trust asks about it again.** The CLI's trust question opens with its highlight on "No, exit", and cockpit answered every dialog it saw with a bare Enter — harmless while that dialog opened on "Yes, I trust this folder", and a crash once the order changed: Enter chose Exit, the CLI quit with code 1, and the session showed "claude exited during startup" instead of the trust card. Cockpit types nothing at the dialog now and reports the directory it is waiting on, so the card can grant it.

## [0.8.0] - 2026-10-10

### Added
- **CommandCode as a provider.** Its one key serves two wires, and its catalogue says per model which: the Claude models answer only `/messages`, the other 76 only `/chat/completions`. Every built-in before this was one wire or the other, so the proxy now routes on the model a request names — Anthropic-wire models are relayed verbatim, the rest translated. The catalogue is public, so the model list and the plan's models show before a key is connected; the plan meters credits ($14 per 5 hours, $35 per 7 days, $70 per month) rather than publishing per-token prices, so the usage view counts exactly and estimates spend.
- **A status dot on the cockpit assistant.** The assistant is an ordinary session that is never pinned to the sidebar, so nothing watched it: a question it was waiting on, or a turn that ended while its modal was closed, showed nothing anywhere. Its footer button now carries the same dot a session row does — blue for a request waiting on you, yellow while it works, green for a turn you have not read — and opening the modal counts as reading it.
- **What a subagent runs on.** An agent's transcript names the model and the thinking level it is using, read from the agent's own transcript rather than its launch, which records a model only when the caller overrode one. The level is the one the CLI writes per turn, so a change mid-run reads as the current one.
- **The footer's pages open over the session.** Jobs, Inbox, Issues and Settings open in a modal instead of replacing the page you were on, and close back to it. On by default; the appearance setting turns it off to navigate as before.
- **Hold a message for the end of a turn.** A long press or right-click on Send while Claude works offers Send now or Send when Claude finishes, the second holding the message in cockpit's queue and sending it as a turn of its own once the current one ends. A plain tap still sends now.
- **Claude Haiku 5.5.** It takes the alias default, so a session or job on bare `haiku` now spawns on it, with a 1M window and thinking across the full low-to-max range. Haiku 4.5 stays selectable as a previous generation.
- **A sandboxed job can keep state in its own folder.** A job is told to keep state in `~/.cockpit/jobs/<id>`, which the sandbox denied along with the rest of cockpit's directory. A sandboxed run now has that one folder writable; the jobs root and every other job's folder stay closed.
- **MCP server secrets are masked until clicked.** The server page shows header and environment values as dots, with an eye button on each to reveal it. Those values are where API keys and bearer tokens live, and the page is as easily read over a shared screen as any other.
- **Authenticate MCP servers from Cockpit.** The MCP servers page lists what Claude Code itself reports, account connectors included, with the result of its health check on each one. Connectors live on the Claude account rather than in a config file, so the CLI is the only thing that can see them. Authenticate runs Claude Code's own sign-in: a connector hands back a URL to authorise at on claude.ai, and a server that speaks OAuth hands back its authorisation URL and takes the URL the browser was then redirected to. Signing in replaces the credentials a server already holds, so the dialog says a half-finished sign-in can leave a working server disconnected.
- **Update every plugin at once.** The Installed tab gains Update all, which updates each plugin from its marketplace source one at a time and reports how many were updated and which failed. Updating used to mean opening each plugin in turn.
- **Chain scheduled jobs.** A job can now wait on other jobs with an After jobs schedule, and runs once every job it waits on has completed successfully since its own last run. A failed run holds it back until that job next succeeds, a job cannot wait on itself or on a job that waits on it, and the assistant's job tools can set it up too.
- **Message Claude while it works.** On the PTY runtime, a message sent during a turn goes to Claude straight away. Claude reads it with its next tool result and carries on with it in mind, as the terminal CLI does. A turn that ends first runs the message next without the session going idle in between, and Esc makes Claude take it up at once. Commands, and messages sent while a card is open or a compaction runs, still wait in the queue.
- **Select inbox messages to act on together.** A Select button puts a checkbox on each message. Pick them one by one, or all at once from the count, then mark them read or unread or delete them in one go. Before, it was one message at a time, or everything through Mark all read and Clear all.

### Changed
- **An agent's transcript opens over the page.** Clicking an Agent card, or an agent's row in Background Tasks, opens its transcript in a modal instead of expanding it inline, full screen on a phone. It opens at the latest message and follows the agent while it works, and Back closes it.
- **The model pill names the provider, and takes the room it needs.** With several providers serving one catalogue, the model name alone did not say which one a session runs, so a provider-qualified pill now reads "OpenCode Go · DeepSeek V4.1 Flash". It hugs a short label and grows to the width of the row for a long one, instead of ellipsising at 60% with the rest of the row empty.
- **Installing resolves no advisories.** `next` moves to 16.4.0 (the critical Windows remote-code-execution fix) and the MCP SDK to 1.32.1 (an OAuth client could send credentials to an authorization server the server chose); every other advisory had a fix inside its existing range, so `express`, `postcss`, `source-map-js`, `fast-uri`, `ip-address`, `nanoid`, `hono`, `body-parser`, `qs` and `baseline-browser-mapping` moved up with them. Fourteen advisories, one of them critical, become none.

### Fixed
- **A reset of Claude Code's own config no longer costs jobs their MCP servers.** The CLI treats one unreadable read of `~/.claude.json` as corruption: it copies the file aside and carries on from defaults, which have no MCP servers at all. Nothing said so, and the next job that needed gmail or conduit ran without it and reported success. Cockpit now keeps its own record of those servers, puts them back when the file comes back reset (from its own copy, or from the CLI's own backup when the file is unreadable), says so in the inbox, and fails a job whose servers are configured nowhere with a message naming them. Cockpit's own writes to that file no longer leave the shape that triggers the reset: a shorter document is padded rather than truncated, so a reader never catches a half-written file.
- **A connect failure no longer reads as a rejected key.** All three key-syncing cards answered "401" for any failed first sync, so a provider that could not be reached looked like a key that was refused — and on OpenCode Go, whose model list is public and accepts any key, that could only ever have been the former. A transport failure now answers 502 and says so; only a provider that really checks its key answers 401.
- **A long press on Send no longer closes the dialog it opened.** Lifting a finger makes the browser replay the touch as a mouse click at the same spot, which by then landed on the dialog's backdrop and dismissed it, so the press looked like it did nothing. Cancelling the release's default stops it.
- **Typing over the send dialog keeps the keyboard.** Choosing either option handed focus to the button and dropped the on-screen keyboard, mid-message, taking the room the dialog sits in with it. Nothing in the dialog takes focus now.
- **An image a tool returns reaches the model through the format proxy.** On the OpenAI wire an image cannot ride inside a tool message, so a `Read` of a screenshot was flattened to the literal text "[object Object]" and the model was shown nothing at all. The picture now travels in the user turn that follows the tool result, the tool card shows it, and a model whose catalog entry says it cannot take images is told one was left out instead of being sent one it would refuse.
- **A scheduled job that has never run catches up a missed run.** When the server starts after a job's time has passed, the job runs within a minute unless it is set to skip missed runs. That only worked for a job with a run behind it, since the check looked back from the last run, so a job due before the server was ever up never ran at all. A job with no runs now counts from when it was last saved.
- **Jobs created without a runtime run on PTY and say so.** A job created through the assistant's tools without a runtime was saved with none. It ran on PTY, but its page showed Stream. New jobs now store PTY, and a job saved before this shows PTY, the runtime it actually uses.

### Internal
- Test suites no longer inherit `CLAUDE_CONFIG_DIR` from the shell. It takes precedence over the home directory cockpit resolves, so a suite that mocked a fake home read the developer's real Claude directory instead — three suites failed inside a container that exports it and passed everywhere else.

## [0.7.0] - 2026-09-29

### Added
- **Auto permission mode.** Sessions get a Manual / Auto / Bypass selector in place of the bypass toggle. Auto hands each decision to the CLI's own safety classifier, which approves plan-safe calls and still raises cockpit's card for the rest. It is offered for Anthropic models only, because the classifier runs on the session's own model and a slow one times out and blocks the call outright; moving a session onto a non-Anthropic model drops it back to Manual. While Auto is on, the session settings icon turns green, as it turns orange for Bypass.
- **A default permission mode.** Session defaults offer Manual / Auto / Bypass in place of the old Bypass toggle, and a new session starts in whichever is chosen. A saved Bypass default carries over as Bypass. Auto falls back to Manual for a session on another provider's model, scheduled jobs keep their own setting, and a session now keeps the mode it started in across a restart instead of following a later change to the default.
- **A default sandbox.** Session defaults can turn the Bash sandbox on for new sessions, with a default network allowlist. Scheduled jobs and the cockpit assistant are never sandboxed by it, a host that cannot enforce a sandbox starts sessions without one, and existing sessions are left as they are.
- **Shared sandbox rules, kept in Claude Code's own settings.** Settings → Sandbox edits the `sandbox` block of `~/.claude/settings.json`: allowed and denied domains, commands run outside the sandbox, writable and unreadable paths, Unix sockets and local ports, and whether a blocked command may ask to be retried outside it. Every sandboxed Claude session reads that file and picks up a change straight away, in cockpit or not, and a session's own domains are added on top. Each session's settings file no longer carries a copy of the block, which kept a removed rule alive until the session restarted.
- **A sandbox switch per scheduled job.** Off by default, in the job editor and in the assistant's job tools. A sandboxed job runs under the shared rules; the session default never reaches it.
- **The session panel shows the mode Claude Code reports.** Claude Code reports its permission mode on every hook, and cockpit now passes it through. The settings icon's colour follows the reported mode and turns red when it is not the one chosen, and the panel says which mode Claude Code is in and what that means.
- **A Bash sandbox per session.** A Sandbox toggle in the session options, with a network-domain allowlist, runs the CLI's Bash inside an OS-level sandbox, where sandboxed commands skip the permission prompt and the OS boundary is the safety net. It needs host support (always on macOS, bubblewrap and socat on Linux), and where that is missing the toggle is disabled with the reason rather than offering a sandbox that does nothing. PTY runtime only.
- **A Kanban board, and statuses per project.** The issues page gains a Board view where dragging a card between columns changes its status. A project can hide built-in statuses it does not use and add its own, ordered and coloured. The built-in lifecycle stays the fixed contract the pipeline skills and status-triggered jobs rely on, so existing projects behave exactly as before. A column that still holds issues stays on the board even if its status is disabled, and a custom status cannot be removed while issues sit in it.
- **Delete an issue.** From the UI only, and the issue's attachments go with it. Agents and jobs still retire an issue by cancelling it, so a model cannot erase the record of why it did. A deleted key is never handed out again, since it names the issue in branches, PR titles and other issues' comments.
- **Trust a directory from the session.** A session opened in a directory the CLI had never seen failed with a spawn error that named nothing you could act on, because the CLI's trust dialog is invisible to cockpit. It now shows a card naming the directory, with a button that records the trust and starts the session. It is explicit every time, with no setting and no silent grants. The grant is the one the CLI's own error message describes, merged into `~/.claude.json` and swapped in atomically, since the CLI writes that file on its own schedule.
- **Session token totals and cache hit rate.** The Context Usage panel adds what the session has spent (input, output, cache read, cache write) and the share of prompt tokens served from cache, summed across `/clear` so earlier spend is not lost.
- **Turn timing.** A live counter beside the spinner shows how long the current turn has been running, counted from your message, and it carries on from there when you leave a running session and come back. Each reply shows when it landed next to how long it took: "Worked for 2m · 14:32".
- **Provider and model on job cards,** so what a job runs on shows without opening it. A disconnected provider or a delisted model falls back to the raw id rather than a blank line.
- **Replace a gateway's API key.** A connected OpenRouter, Zen, Go or DeepSeek card now offers Replace key. The key field used to disappear once a key was stored, so rotating one meant editing `providers.json` by hand. A new key is validated the same way a fresh connect is, a rejected one leaves the old key in place, and the enabled model set is kept.
- **Claude Opus 5.5, Sonnet 5.5 and Fable 5.1.** Each takes over its alias, so a session or job on bare `opus` now runs Opus 5.5, one on `sonnet` runs Sonnet 5.5 and one on `fable` runs Fable 5.1. Opus 5, Sonnet 5 and Fable 5 stay selectable as previous generations, and anything pinned to them keeps running there.

### Changed
- **Installing cockpit no longer pulls in TensorFlow.** Language detection for pasted code ran on magika, which brings `@tensorflow/tfjs-node` along as an optional dependency: 659MB and six advisories on every install, one of them critical. It now runs on highlight.js, which the page already loads. An install resolves 308 packages instead of 413, takes 550MB instead of 1.3GB, and reports no vulnerabilities. Detection is a little better on a typical paste and worse on a whole file, and a wrong guess only mislabels the paste chip, never the paste.
- **Pinned sessions and reviews move into cockpit's own directory.** They were the only cockpit state kept under `~/.claude/cockpit/`, so relocating or clearing the Claude directory took the sidebar's pins with it. Existing pins are adopted on first read, and the old file is copied rather than moved, so an earlier cockpit still finds it.
- **Zen and Go requests carry a session id.** OpenCode groups a conversation's requests by an `x-opencode-session` header, uses that grouping to keep a prompt cache warm across a turn, and warned that requests without it may be rejected from 6 September 2026. The translation proxy rebuilt every request's headers from scratch and sent none. It now forwards the CLI's own session id, to OpenCode only.

### Fixed
- **A session that enters a worktree keeps working.** Entering a worktree makes Claude Code move the session's transcript from the original directory's project folder to the worktree's, and cockpit went on reading the old path. The chat emptied, nothing Claude did afterwards reached the page, and every message after that was reported as never reaching Claude. Cockpit now finds a moved transcript by its session id, so the live view, reloads and restarts follow it.
- **Scrolling back through a session no longer snaps to the bottom.** On a PTY session every transcript update replaced the chat with the transcript's last 150 lines, so older messages vanished as new ones arrived. That took the message being read with them and left the view at the bottom. An update now keeps what the page already holds, including older messages loaded by scrolling up, and the rendered window no longer slides its top away while you read.
- **Esc during a compaction no longer wedges the queue.** Cancelling a /compact left cockpit waiting on it, because Claude Code reports the cancel only on its own screen, so queued and new messages sat behind it until the session restarted. Cockpit now drops the compaction when you interrupt it or the CLI is stopped, and the chat shows "Compaction cancelled, context not reduced".
- **A compaction is no longer taken as finished early.** Cockpit took any compaction marker in the transcript's last lines as the end of the one in flight, including a marker an earlier compaction left there. It then typed queued messages into a CLI still compacting, where they were retried and could arrive three times. Only a marker or reply written after the compaction was requested counts now.
- **The context gauge drops after a compaction.** PostCompact fires just before Claude Code writes the compaction boundary, and a transcript update landing in between put the pre-compaction reading back. It stayed until the next turn and could set off another compaction on the next message. With no reading since the latest compaction, the post-compact estimate now stands.
- **A sandboxed command's network request can be answered.** A sandboxed command reaching a host outside the allowed domains made Claude Code ask in its terminal, where cockpit could not see it: the command waited out its own timeout, and a message typed meanwhile went into the question, where Enter means Yes. Cockpit now raises it as a card naming the host, with Allow for this session, Always allow and Deny answered through the question's own keys, and holds a message back while one is waiting.
- **Leaving the sandbox always asks.** A Bash call that asks to run outside the sandbox is marked on its card, and neither bypass nor plan mode's read-only shortcut approves it. Cockpit also answers "ask" to it before it runs, so it raises a card in every permission mode, Auto included.
- **Sandboxed commands can no longer read cockpit's own directory.** It holds the key cockpit's login tokens are signed with and the providers' API keys, so a sandboxed command able to reach cockpit's port could have signed itself in and opened a terminal outside the sandbox.
- **Bypass is applied by cockpit itself.** Cockpit asked the CLI for its own bypass mode and approved only the prompts that still reached it, which left the CLI's mode deciding how a session ran. Bypass now keeps the CLI in manual and approves every prompt itself, as the cockpit assistant already did, so a session in Bypass does what you asked for whatever mode the CLI is in.
- **A multi-line message reads back as you typed it.** The CLI has started recording pasted text wrapped in `<pasted_content>` tags, and cockpit types every multi-line message into it as a paste, so those tags appeared around your message in the chat, in the session's title and in prompt history. Cockpit now takes the wrapper off the same way the CLI's own display does, including restoring any tag you pasted in yourself.
- **A failed turn shows the provider's actual error.** An upstream refusal reached you as "CLI error: Unknown error (unknown)". The CLI had printed the provider's sentence to the screen, but the failure hook that follows it carried nothing, and cockpit reported the hook. It now reads the screen first, so the same failure reads "Upstream request failed: This Go model requires Global regions. Select Global in your workspace's Privacy settings to use it. (HTTP 400)".
- **Tool calls stop being blocked by a classifier nobody chose.** The CLI's own default became `auto`, and every session inherited it without asking, so on a slow non-Anthropic model a classifier timeout blocked tool calls outright ("auto-mode safety classifier down"), the cockpit assistant most of all. Permissions are cockpit's job, answered through its own cards, so sessions now ask for manual mode explicitly and use auto only when you pick it. The flag is only passed to a CLI that lists it, since an unknown mode name kills the spawn.
- **Switching model restarts the CLI when the context window changes.** The CLI learns its context window once, at spawn. Cockpit compared only the 200K/1M choice, but a gateway model carries its own window, so switching between two of them left the CLI enforcing the old limit while the gauge showed the new one. One session reached 439,341 tokens against a 128,000 window: the upstream refused the prompt, the automatic compaction failed with it, and the CLI blamed the model with "There's an issue with the selected model". A conversation already too big for the model being chosen is now called out at the moment of the switch.
- **Models whose endpoint refuses tool calls are no longer offered.** The CLI sends its tool definitions on every request, and some OpenRouter variants route to a single endpoint that rejects them, failing with "It may not exist or you may not have access to it" although the model and the key were fine. 68 of 414 synced entries were affected and every one was in the picker. They are filtered on read, so an existing catalog stops offering them at once, and a session already pinned to one refuses to start and says why instead of sending that model id to Anthropic.
- **A message the CLI did not register is resent.** Typing into the terminal has no acknowledgement, and a live message could be swallowed, most often right after dismissing a question, leaving the session spinning on a message the CLI never received. Cockpit now confirms delivery and retypes up to three times, and if all three are lost it says so and stops the turn rather than leaving it running.
- **A message is never typed into a CLI dialog.** With the CLI's setup wizard open, cockpit's blind typing went into the wizard: the message was lost and each retry ticked the wizard's consent checkbox, where one Enter would have accepted it. Cockpit now looks at the screen before typing and, when a dialog is waiting, names it instead.
- **A declined `/compact` no longer wedges the session.** The CLI can accept a compaction and then refuse it ("Not enough messages to compact"), and that path fires no completion hook, so the session read COMPACTING… for the rest of its life with every later message queued behind it. A reply arriving in place of a compaction now releases it.
- **A message queued behind a manual `/compact` is delivered.** It was typed in the moment the compaction finished, while the terminal was still redrawing, and silently lost: the queue emptied and the CLI never saw it. The send now waits until the compaction has landed.
- **Scheduled jobs no longer die silently in an untrusted directory.** A job in a directory the CLI had not seen failed within seconds with "went idle without producing any assistant message", because the CLI raised its trust dialog and cockpit typed the prompt into it. Nobody watches a scheduled run to click a trust card, and choosing a job's directory is already the bigger grant, so a job now trusts its working directory and scratchpad before it starts.
- **Gateway sessions report prompt-cache hits.** The translation proxy passed on no cached-token counts, so every Zen, Go and custom OpenAI-format session showed zero cache for its whole life. Cached tokens now come through without being counted again as fresh input. Usage metering is unchanged.
- **`/cost` shows real numbers on the PTY runtime.** It read a counter only the stream runtime ever fed, so on the default runtime it reported zeros for every session. It now reads the transcript, which also survives a restart.
- **OpenRouter refusals are explained rather than reported as malformed.** A `:free` model's moderation or routing refusal comes back as HTTP 200 wrapping an error object, which the CLI reported as "API returned an empty or malformed response". These are now retried like a rate limit and, if they persist, surfaced with OpenRouter's own message.
- **Bypass covers tool prompts in plan mode.** A session in bypass asked about every tool once it entered plan mode, and Bypass All on those cards did nothing. The CLI enforces plan mode itself before a prompt ever reaches cockpit, so the extra click protected nothing. Approving a plan and answering a question still always ask.

### Internal
- A `publish-release` skill writes down the release steps: changelog, release PR into `main`, tag, `make publish`, then proving the published tarball installs and boots.
- Turning bypass off on the stream runtime asked the CLI for a permission mode it has since retired; the argument is now typed to the two modes it can be.
- Three CI failures that passed locally: a test rejection landing before its handler attached (every file green, exit code 1), a lint error that biome reports but the pre-commit hook does not run, and a test asserting a spawn flag that depends on `claude --help`, on a CI runner with no CLI to ask.

## [0.6.0] - 2026-08-13

### Added
- **Native issue tracking, off by default.** Projects and issues live in cockpit itself, with a list grouped by status, a detail view with markdown descriptions, comments and an audit trail, and a project-grouped browse view with label sub-groups. Every write is attributed to whoever made it — a session, a scheduled job, or you — and a session or job actor links through to its transcript. The tracker is experimental: turn it on under Settings, Appearance, Experimental. While it is off, nothing appears in the UI and the agent cannot see the tools at all.
- **Issues reachable from sessions and jobs.** Seven MCP tools (list projects and issues, read, create, update, comment, attach) are available to the cockpit assistant, to scheduled jobs, and to plain working sessions, so you can ask a session to file what it just found. The actor on every write comes from the caller's token and cannot be set by the model.
- **Jobs triggered by an issue changing status.** A schedule can be an issue transition rather than a clock — "when an issue enters Implementation Ready" — replacing jobs that polled on a timer to ask a question usually answered "nothing". Because a run handles one issue, the scheduler re-checks on completion and keeps going while issues remain, stopping if a run makes no progress.
- **Notifications from a session.** A working session can post to the inbox and push to a named provider, so you can ask it to message you on Telegram or ntfy when it finishes. Rate limited per session.
- **OpenCode Go.** Added as its own built-in provider alongside OpenCode Zen: separate subscription, separate catalog, its own key, model list and pricing, connected the same way as the others.
- **Attachments on issues.** Files attached to an issue are copied into cockpit's own store and served back, so a screenshot outlives the temporary directory it was captured in.
- **Scheduled jobs from a working session.** The job tools — list, read, create, update, delete, run, stop, and read a past run's transcript — are available to plain sessions as well as the cockpit assistant, so you can ask the session you are already in to set a job up instead of relaying through the assistant. A companion tool hands over the job editor's whole menu: which models are pickable and the context and thinking levels each accepts, which MCP servers exist, which notification targets can be pushed to, and what every field defaults to when omitted. Scheduled jobs themselves still cannot reach these tools — a job that could create jobs is a loop with nobody watching it.
- **A 200K/1M context choice for gateway models.** Where a provider's published context figure is wrong, a model can be marked in the model browser as offering both sizes, and it then gets the same 200K/1M chips Anthropic models have in the session picker. The session's pick drives the context gauge and the CLI's own auto-compact together, and it survives the daily catalog resync that would otherwise restore the published figure.

### Changed
- **The issue pipeline runs on cockpit's tracker instead of Linear.** The refine, implement, accept and review skills and their reviewer agents now speak to the native tools, with per-project keys in place of a single prefix. The refinement and implementation human gates, previously one status told apart only by Linear's state groups, are now distinct statuses: Plan Review and Code Review.
- **New scheduled jobs default to the PTY runtime**, matching what sessions use.

### Fixed
- **Sessions on a reasoning model no longer die mid-task.** A session on OpenCode Zen would stop after a tool call with "Unknown error", because the translation proxy sent the model's own reasoning back incompletely. Both halves are fixed: a turn's thinking is returned as it arrived, and a tool-calling turn that did no reasoning still carries the field the upstream requires.
- **Scheduled jobs can use any connected provider.** The job editor's provider list offered only Anthropic, so a job could not be pointed at OpenRouter, Zen, Go or DeepSeek even when connected.
- **`create_job` no longer drops most of what it is given.** The tool advertised nineteen fields and assigned five.
- **Model, context and thinking survive a restart.** Session defaults reset to 200K on restart, and the first message of a session could trigger a spurious compaction.
- **Session settings stop reverting.** Renaming a session, or changing its model or thinking level, could be quietly undone by something as ordinary as opening a file tab. Session preferences are compiled into two bundles that both run in the one server process, each caching the whole file and rewriting it wholesale, so the copy behind the file-tab route stamped its stale snapshot over what the websocket side had just written. Each copy now notices when the file has changed underneath it.
- **A session remembers what it was created with.** Only the runtime was stored, so a session created with a name, a model, a context size or a thinking level came back after a restart named after its working directory and on whatever the current default happens to be. In a real installation, 213 of 258 stored sessions carried no model at all.
- **A question no longer appears as two identical cards.** Three separate causes, each producing the same symptom of two prompts with separate selections where choosing in one left the other blank: every message holding an unanswered question bound to the first pending request rather than its own; the same turn arriving under two different message ids, because the live path and the transcript re-parse identify a message differently; and the notification rescue raising a second, synthetic request for a question the hook channel was already waiting on — that one also blind-selected the first option if answered.
- **A newly created session stays in the sidebar.** Created from the session list, it appeared and then vanished until a refresh, because two overlapping list refreshes could land out of order and the older response won. The list now discards a superseded refresh.
- **The in-progress indicator follows the session, not its agents.** A session that launched a background agent kept flipping between states: the spinner restarted on an idle session waiting for input, because the agent's own tool calls drove status; a session that resumed after an agent finished never got its spinner back at all; and the sidebar showed nothing while work carried on. Cockpit now takes the running-work list from the CLI rather than inferring it from subagent start and stop events, which do not mean what they appear to (a stop arrives while the same message still reports the agent running, and stops also arrive for agents that never started). A session with background work running shows a dimmed pulse in the sidebar and still accepts input, and a message you send while an agent works still shows a spinner for your own turn.
- **An agent card keeps its spinner across a reload.** The transcript records a background agent's launch as complete the moment it returns, so a freshly loaded page read a running agent as finished until the next status report happened to arrive, around ten seconds later. Cockpit now hands a connecting page the work already in flight, alongside the pending prompts it already replayed.
- **Approval cards name the job or notification provider** instead of showing a uuid.
- **The input box stops growing past its container** on mobile, so a long message stays scrollable instead of pushing its own end off screen.
- **`/compact` no longer hangs.** Triggering a compaction from the menu or by typing the command raised the indicator and then did nothing, permanently: the trigger was queued behind the very flag it had just set, and that queue only drains when the compaction it is waiting for finishes.
- **A background agent's transcript renders.** An Agent card reported no transcript while the file sat on disk, because a background agent's card is built from a hook carrying the agent id rather than the tool-use id the lookup expected.
- **Sessions on a gateway provider show their context gauge again.** On OpenCode Zen, Go, OpenRouter or a custom OpenAI-format provider the context indicator was missing entirely: the translation proxy passed on only the output half of each turn's token usage, so the gauge saw an empty window and hid itself. It also means those sessions were compacting on the CLI's estimate rather than a real figure.
- **A bypass that never took effect no longer stops a session dead.** Where an account or its settings decline bypass permissions, the CLI runs in its ordinary mode while cockpit's indicator still claimed bypass was on, and the resulting prompts appeared as a dialog cockpit could not display — the session simply stopped, with no visible reason. Cockpit now spots the mismatch and, while bypass is on, answers those dialogs on your behalf. It says nothing about it in the chat, because there is nothing left for you to do; the mismatch is recorded in the debug log.
- **A job's `Bash` rule stops refusing ordinary data.** A `Bash curl` rule rejected any command containing a shell metacharacter anywhere, so a POST whose body held a semicolon or an ampersand was denied while the same request without them went through — and an unattended run has nobody to ask. Quoting is now honoured, so a quoted `;` is data. A pipe is refused, since it runs a program the rule never named; that also means no single rule can permit a pipeline.
- **MCP tools work for servers whose name contains a hyphen.** Every call from a job to such a server was denied, because the name was normalised on one side of the comparison only. Separately, an `allowedTools` entry naming an MCP tool now actually grants it — the entries were accepted by the editor and printed in the run's prompt while doing nothing at all.
- **A job's schedules are checked when saved.** A malformed schedule stored cleanly and then simply never fired; the shapes are also now described in the tools that write them.
- **A finished run is no longer recorded as a failure** because it volunteered an error block saying nothing went wrong.

### Internal
- The published tarball ships a prebuilt `.next`, so `next`, `react` and `react-dom` are now exact versions rather than ranges. Published 0.5.0 allowed a newer Next to run bundles an older one compiled, which broke every dynamic route on a fresh install while static pages kept returning 200.
- A fresh install could not build for a while: TypeScript 7 drops the file Next probes to detect a TypeScript project, so the path alias silently stopped resolving while type checking still passed. Pinning to TypeScript 6 fixed it at the time; the Next version shipped here no longer relies on that file, so this release runs TypeScript 7 with the pin lifted.
- CI now runs a real production build from a clean install on every push, and refuses a range on the three pinned packages — the two checks that would each have caught the above.
- Running the test suite deleted the developer's own cockpit password. Tests now get a throwaway config directory by default, so a suite that forgets to isolate cannot reach real state. They also clear every `COCKPIT_*` variable first: `make start` and `make dev` export several, a session cockpit spawns inherits them, and a suite run from inside cockpit therefore behaved differently from one run in a plain shell.
- The job tools no longer present `bypassPermissions` as the fix for a refused tool. `create_job` described it as the alternative to listing tools, and `update_job` — the call made to repair a failing job — did not describe it at all, so a session reached for it the moment a job hit a permission wall.
- `@pierre/theme` is declared directly rather than left to be inferred as a peer dependency. A generated lockfile placed the only copy where the package that imports it could not see it, and the build failed on an unresolved import; a declared dependency cannot be dropped that way, and a lockfile missing it now fails the install outright.
- `make start` now installs the way a user does: node_modules and `.next` are wiped, dependencies come from the lockfile, and the tarball is built from that rather than from whatever the working tree held. It also stops silencing npm, since deprecation, peer and engine warnings are what a user reads on install. That is the gap a published release fell through once, and how a stub types package sat in the tree warning on every install without being noticed.
- Dropped `@types/uuid`: uuid ships its own types, so the stub only produced a deprecation warning. Removed from the lockfile by hand, because regenerating it with the npm here strips the `libc` fields that let npm skip a native binary built for the wrong C library.
- The integration suite could not run from inside a Claude Code session. The harness passed its whole environment to the cockpit server it spawns, so the session's own `CLAUDECODE` and `CLAUDE_CODE_*` variables reached the CLI underneath, which then took itself for a nested invocation and wrote no transcript. Every test asserting on a reply failed with an element that was never there, while the mock API showed the request arriving — a harness fault that reads exactly like a cockpit one. The mock can also hold a turn open now, so a test can keep a background agent alive long enough to observe.

It runs as a single persistent session backed by a `cockpit-config` MCP server. Read tools (list/get) answer questions about your jobs, providers, MCP servers, app settings, and notification settings and run automatically. Write tools (create/update/delete/run/stop a scheduled job, add or edit providers, MCP servers, settings, and notification providers) are shown as a proposal card you approve or reject before anything changes. The root cause was cockpit's two module graphs (the custom server and the Next.js API routes) each caching `providers.json` independently, so a provider saved through one was invisible to the other until a restart. If the CLI isn't running yet — for example right after a context-size switch — it spawns one so the breakdown is consistent rather than silently falling back to a one-line estimate. It no longer leaves the session stuck on "processing", and ANSI colour codes are stripped from the output.

The transcript watcher recomputes "used" from the most recent assistant turn, which right after a compaction is still the large pre-compaction one until the next reply lands. Transcript usage now resets at the compaction boundary, so the estimate holds until a real post-compaction turn arrives.

Keyboard-open detection compared the visual viewport against the live layout viewport, but the app's `resizes-content` viewport shrinks both together, so the ratio never tripped. Detection now measures against the tallest height seen.

The token is fixed and the badge now uses the shared destructive `Badge` component.

- **Terminal scrollback on detach.** Corrected the detach-offset trim math and scoped the detach to the closing socket, so one client disconnecting no longer truncates another's scrollback.
- **Clearing job duration and retention fields.** The max-duration and retention number fields can be cleared while editing without snapping back to 0.
- **Pasted text in queued messages.** A queued message that flushes now shows pasted text as a chip instead of expanding to the full pasted file content.
- **Misc layout.** Job card title spans the full width; settings version cards keep their height while loading (no jump); the all-sessions header shows only the usage icon; tool-card messages fill the column width; the new-session dialog keeps its action button visible on small viewports; run-detail action buttons wrap on mobile instead of overflowing; plugin card names stay readable on narrow screens; and clicking a file path in a tool card no longer nests a button inside a button.
